# HANDOFF — USAGE: счётчик живых установок

> Линия заведена 2026-08-21. Код влит в 1.27.70 и спит под флагом `usage-stats` (OFF).
> Пока флаг выключен, приложение ведёт себя ровно как до линии: ни одного байта наружу,
> ни одного лишнего запроса, ни одной новой строки в настройках.

## Зачем

Единственный вопрос, на который у проекта нет ответа: сколько людей им реально пользуются.
Не «сколько скачали», а сколько открывают, тренируются и спрашивают коуча. Ответ нужен,
чтобы решать, что чинить дальше — сейчас приоритеты ставятся вслепую.

Цена ответа зафиксирована жёстко: три счётчика, ноль содержимого, выключаемо в один тап.
Всё, что выходит за эту рамку, — новая карточка и отдельное решение, а не «раз уж есть канал».

## Что уже стоит (1.27.70)

- `js/usage.js` — весь механизм: ворота, санитайзер, очередь, досылка.
- Флаг `usage-stats` в `js/flags.js`, дефолт `false`.
- Три точки вызова: `js/app.js` (app_open, в `defer`), `js/workout.view/handlers.js`
  (workout_completed, после сохранения сессии), `js/claude.store.js` (coach_message, выше
  приватного гейта — локальный ответ Insights для пользователя тоже «спросил коуча»).
- Строка + тумблер в карточке «Приватность» (`js/privacy.view.js`), RU/EN в `js/locale.store.js`.
- `/_vercel/*` мимо service worker (`sw.js`) и отдаёт 404 из `server.js`, если платформа
  не перехватила запрос сама.
- `test/usage-stats.test.js` — 22 теста: белый список имён, белый список полей, четверо
  ворот, очередь на живом IndexedDB.

### Пять ворот, все должны быть открыты

| Ворота | Где живёт | Кто закрывает |
|--------|-----------|---------------|
| флаг `usage-stats` | `js/flags.js` (дефолт OFF) | разработчик |
| DNT / GPC | сигнал браузера | пользователь, на уровне ОС/браузера |
| самоисключение | `localStorage['ap-usage-exclude']` | автор: `Usage.excludeSelf(true)` |
| тумблер | `DB.Settings['usage.enabled']`, синкается | пользователь, в «Приватности» |
| прод-хост | `https:` + не localhost/LAN | среда |

`Usage.state()` в консоли отвечает, какие именно ворота закрыты: `flag` · `dnt` ·
`excluded` · `off` · `host` · `ok`.

### Что уходит наружу

| Событие | Payload | Когда |
|---------|---------|-------|
| `app_open` | `version`, `mode` | один раз на сессию вкладки |
| `workout_completed` | `type` (push/pull/legs) | сессия сохранена в историю |
| `coach_message` | нет полей вообще | пользователь отправил вопрос |

Санитайзер режет по белому списку ПОЛЕЙ, а не по чёрному: незнакомый ключ не проходит,
даже если его добавят в вызов по недосмотру. Не-скаляр не проходит под любым ключом.
В режиме `airgap` payload срезается целиком — наружу идёт голое имя события.

### Очередь

`DB.Settings['ap-usage-queue']` (не отдельный store — схему не мигрировали). Потолок 50
записей, TTL 7 дней, режется голова. Префикс `ap-` обязателен: без него ключ уехал бы в
облачный синк и второе устройство посчитало бы чужое недосланное повторно — на это стоит
отдельный тест. Досылка — на событие `online` и на следующем `initUsage()`.

## Карточки

### USAGE-1 — включить Web Analytics в проекте Vercel (за Gio)

**ЦЕЛЬ.** В `gio-g7/athlete-pro-v7` → Analytics → Enable Web Analytics. Без этого
`/_vercel/insights/script.js` отдаёт 404, `script.onerror` пишет строку в консоль и
счётчик молчит. Кода не касается.

**ГДЕ СТОП.** Дашборд Analytics открывается и показывает хотя бы pageview.

**Риск, который надо проверить глазами:** `vercel.json` держит легаси-секцию `routes` с
`{ "src": "/(.*)", "dest": "/server.js" }`. Ожидание — платформа перехватывает `/_vercel/*`
до пользовательских маршрутов. Если нет, запрос дойдёт до `server.js` и получит честный
404 (специально, чтобы не прилетел `200 text/html` и синтаксическая ошибка). Проверка
одной командой после включения:

```bash
curl -sI https://<прод-домен>/_vercel/insights/script.js | head -3
```

`200` + `content-type: application/javascript` — путь открыт. `404` — платформа не
перехватывает, и линия упирается сюда: тогда карточка USAGE-1b (перевести `vercel.json`
с `routes` на `rewrites`, где `/_vercel/*` резервируется корректно).

### USAGE-2 — флип флага и полевой чек

**ЦЕЛЬ.** После зелёной USAGE-1: `Flags.setFlag('usage-stats', true)` на своём устройстве,
следом `Usage.excludeSelf(true)`, чтобы автор не попал в счёт. Убедиться, что события
доезжают до дашборда (проверять с другого устройства, своё исключено). Затем поднять
дефолт в `js/flags.js` отдельным PR.

**ГДЕ СТОП.** В дашборде видны все три кастомных события; строка и тумблер в
«Приватности» ведут себя как ожидается на всех трёх режимах приватности.

**НЕ ТРОГАТЬ.** Список событий. Четвёртое событие = новая карточка с отдельным решением,
а не строка в `EVENTS`.

### USAGE-3 (бэклог) — `track()` из самого `@vercel/analytics`

Сейчас `js/usage.js` повторяет путь пакета вручную (инжект того же скрипта, тот же вызов
`window.va('event', ...)`, те же `data-sdkn`/`data-sdkv` версии 2.0.1). Причина — проект
без сборщика: голый специфер браузер не разрешит, а импорт-карта живёт в `index.html`,
который в момент заведения линии держала SPLASH-1.

Когда SPLASH-1 закроется, стоит взвесить: тянуть пакет через импорт-карту + шаг сборки
(копия `dist/index.mjs` в репо) или оставить как есть. Полезная поверхность пакета — две
функции, вся остальная машинерия там про фреймворки. Решение за LEAD; по умолчанию —
оставить, версия SDK в `js/usage.js` обновляется одной строкой.

## Открытый вопрос к Gio

Тумблер сейчас **opt-out**: под включённым флагом счётчик работает, пока его не выключили.
Это осознанный выбор — opt-in при трёх обезличенных счётчиках даёт выборку, по которой
нельзя принимать решения. Но проект стоит на приватности по умолчанию (`airgap` для новых
установок), и обратный выбор тоже защитим. Меняется одной строкой в `initUsage()`:
`_enabled = stored === null ? true : !!stored` → `false`.
