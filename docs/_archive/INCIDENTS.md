# Разборы инцидентов — почему правила такие

> Вынесено из `CLAUDE.md` 2026-08-02. В правилах остались сами правила; здесь — история,
> которая их купила. `CLAUDE.md` — поведенческий контракт, а не журнал инцидентов:
> агенту нужно правило, а не рассказ, и рассказ платится токенами каждую сессию.
>
> Читать при вопросе «а почему так?» или когда правило кажется избыточным.

## PP-6 — ветка на 233 коммита позади, все гейты зелёные (2026-07-29)

Самый дорогой инцидент проекта: ветка была бы влита и откатила бы четыре закрытые карточки.

**Что случилось.** Агент работал на базе от 28 июня. Прогнал pre-push SAST/SCA — зелено.
Прогнал тесты — честные 211/211. Отчитался «всё хорошо». В main на тот момент было
385 тестов и 233 новых коммита.

**Пять отдельных отказов, каждый выглядел нормально:**

1. **Зелёный гейт отвечает только на свой вопрос.** SCA говорит «нет уязвимостей», SAST —
   «стиль цел», тесты — «эта сюита прошла». Ни один не отвечает «код написан по сегодняшнему
   main» — все три спокойно зеленеют на коде трёхнедельной давности.
2. **211/211 было сигналом тревоги, а не успеха.** Зелёный на неполной сюите — не зелёный.
   Число в гейте надо сверять с базой main, а не радоваться проценту.
3. **Протухший `CLAUDE.md` = протухшие правила.** В той ветке он предписывал «Рабочая ветка:
   `2026-04-14-byoi`» — линию, упразднённую O-3 ещё 25 июля. Агент исполнял инструкцию
   добросовестно, просто апрельскую. Отсюда: если агент ведёт себя странно — сперва
   `git log origin/main -- CLAUDE.md` и сверка его базы, а не разбор «почему он не читает правила».
4. **Локальный хук не защищает сам по себе.** `core.hooksPath` абсолютный и смотрит в
   КОРНЕВОЙ чекаут. Протух корень — протухли хуки у всех worktree сразу, молча. Так и вышло:
   гард лежал в main, а корень стоял на коде 28 июня, и хук с гардом не запускался ни у кого.
   Правило общее: **правила и гарды, живущие в чекауте, дрейфуют вместе с чекаутом**;
   единственный недрейфующий слой — CI и настройки GitHub. Поэтому дубль в CI обязателен.
5. **Ожидаемого кода нет на месте → сверься, не строй теорию.** Агент заметил отсутствие
   заплатки PP-5 и объяснил это «она на параллельной ветке» — а она была влита в main и
   просто отсутствовала в старой базе. Верная реакция на «странно, тут этого нет»:
   `git log origin/main -- <файл>`, а не гипотеза.

**Что построено:** `scripts/check-branch-drift.mjs` в pre-push и job `drift` в CI. Блокирует,
если файлы, которые ты правил, с момента твоей базы переписали в main. Отставание само по себе
не блокирует — блокирует пересечение. Обход осознанный: `DRIFT_OK=1 git push`.

**Побочный урок (baseline).** При замере прыжка на main «бага не было» — его маскировала
заплатка PP-5. Baseline обязан воспроизводить баг: снимать заплатку в обеих сборках, три прогона.

## csp-soft-delete — упразднённый trunk пережил своё упразднение (2026-07-26)

Долгоживущий trunk `claude/csp-soft-delete` был второй точкой интеграции и стоил потери
влитого PR#9. Карточка O-3 его упразднила: правила переписаны, локальные ветки и worktree
сняты, remote-ветка удалена.

**Мина:** он же был **дефолт-веткой GitHub** — нашлось только при попытке физически удалить.
Три места из четырёх закрыты, четвёртое молча продолжало работать.

**Правило:** вывод инфраструктуры из эксплуатации = чеклист всех мест прошивки —
правила и доки · локальные ветки и worktree · remote-ветка · настройки GitHub (default branch,
protection) · Vercel. Дефолт-ветку теперь сторожит `npm run preflight`.

**Побочно:** строка «Main branch: claude/csp-soft-delete» в git-статусе неделю была видна всем
агентам, и никто не спросил «почему». Увидел странное в статусе или выводе — один раз спроси
или заведи карточку.

## Три инцидента оркестрации (2026-07-25)

Потеря влитого PR#9 · прод-фикс провисел невлитым · битый git-email → HTTP 500 на create-PR.

Полный разбор с пятью корнями и карточками O-1..O-7 — `docs/handoff/HANDOFF_orchestration.md`.
Оттуда выросли: DoD-лестница (готово = на проде, не «закоммичено»), ancestry-ступень
(`git merge-base --is-ancestor`), `npm run smoke:prod`, `npm run preflight`, `npm run inventory`.

**Гоча git-email:** `user.email` без `@` даёт HTTP 500 с пустым телом на `POST /pulls`, при этом
push и compare работают нормально. Диагностика — `git log -1 --format=%ae`.

## Гигиена репо H-1 (2026-07-25)

4492 → 270 отслеживаемых файлов: вендоренный 40 МБ сторонний репозиторий, девять одноразовых
отладочных скриптов, куча артефактов. Ничего из этого не приехало одним плохим коммитом — оно
наросло, потому что **ничто не падало, когда оно появлялось**.

Отсюда `test/repo-hygiene.test.js`: правила про *форму*, а не про имена файлов, чтобы будущий
`fix_escape2.js` ловился без обновления чёрного списка. Новый док в корне = красный `npm test`.
Это осознанно: 15 доков в корне выросли именно из «положу пока сюда».
