# HANDOFF — MOTION-PRO

> Линия премиальной моторики. Заведена 2026-09-17 по разбору «приложение выглядит просто».
> **Очередь: после `MOTION-FIX`.** Привязка к LAUNCH-10 снята решением Gio 20.09 —
> линия разморожена. Зависимость от `MOTION-FIX` остаётся жёсткой: MO-* ложатся на
> навигацию, а её чинит именно `MOTION-FIX`. Не брать по дороге.

## Постановка

Претензия Gio была «не хватает анимаций». Разбор кода претензию не подтвердил: в репозитории
52 `@keyframes`, ~161 `transition`, восемь ease-токенов (`css/base.css:116-123`), четыре
duration-токена, пружина на физике (`js/shared/spring.js`), View Transitions в навигации
(`js/shell.js:81`), `prefers-reduced-motion` в пяти CSS-файлах и трёх JS-гейтах.

Плоско читается не от нехватки движения, а от трёх вещей:

1. **Переход экранов — глобальный crossfade без направления.** `view-transition-name` —
   ноль применений; `css/base.css:872-876` красит только `::view-transition-old(root)`.
   Ничто не превращается одно в другое.
2. **Данные не оживают.** `bar-grow` — одно место (`css/profile.css:975`), скелетоны — только
   `intel.css`, числа появляются готовыми.
3. **Один уровень высоты вместо трёх.** AIR объявляет page / flat-AIR / floating glass; на
   Профиле виден один — всё `--c-bg-2` + hairline, одинаковый вес. Это не motion-задача,
   она уже лежит в PP-4 (три ритма). Здесь не дублируется.

## Фильтр отбора

Критерий Gio: vanilla JS, 60 fps+, молниеносность, стабильность. Приёмы отбирались по нему,
а не по зрелищности.

| Приём                                      | JS               | Поток                 | Вердикт                      |
| ------------------------------------------ | ---------------- | --------------------- | ---------------------------- |
| `linear()` easing                          | 0                | тот же `transform`    | взят — MO-1                  |
| `@starting-style` + `allow-discrete`       | **минус 10 rAF** | opacity/transform     | взят — MO-2                  |
| scroll-driven `animation-timeline: view()` | 0                | вне main thread       | взят — MO-3                  |
| count-up через `Spring`                    | rAF (есть)       | repaint текста        | взят с ограничителями — MO-4 |
| shared-element `view-transition-name`      | 0                | снимки композитора    | взят последним — MO-5        |
| `@property` + анимируемый градиент         | 0                | **paint каждый кадр** | отклонён                     |
| Параллакс на скролле                       | rAF              | main thread           | отклонён                     |
| Blur-переходы поверхностей                 | 0                | дорогой на OLED       | отклонён                     |

**Почему отклонены.** Анимируемый градиент и blur-переход перекрашивают площадь каждый кадр —
это ровно то, за что PERF-2 (`test/css-infinite-composite.test.js`) уже держит гард: одна
мигающая точка 8 px на `background-color` давала 602 Paint за 5 с простоя. Параллакс считает
позицию на main thread и умирает первым при джанке. Все три дают «дорого» на демо и режут
кадры на живом телефоне — против критерия.

**Поддержка.** `linear()`, `@starting-style`, `allow-discrete`, scroll-driven — Baseline,
Safari 17.4+/18. Все четыре — прогрессивное улучшение: на старом движке элемент просто
появляется без анимации, поведение не ломается.

## Порядок

По возрастанию риска, не по зрелищности. MO-5 даёт больше всего и идёт последним сознательно:
он ложится на навигацию, а её чинит MOTION-FIX.

**Вторая волна (разбор прототипов TONNAGE, 25.09):** `FRAME-1` → `PLATE-1` (гриф) → `RANK-1` →
`HOLD-SAVE` → `RPE-HEAT`, после MO-2b. FRAME-1 первым: без замера кадров остальные судятся на глаз.
Прототипы — у Gio вне репо (`tonnage_motion_wow.html`, `tonnage_rpe_and_rank.html`,
`tonnage_epic_lab.html`); переносится приём, не код. Отсеяно: тахометр RPE как ввод-слайдер,
формула рангов прототипа (без пола, поправка на рост перевёрнута, «IPF» без источника), радар
силы (есть `js/profile.view/hexagon-radar.js`), бесконечная дрожь стрелки, удержание на подходе.
Орбита отдыха по пульсу — `ORBIT-1`, заморожена в `docs/_archive/HANDOFF_hr_orbit.md`.

**Общие дефекты прототипов — не переносить:** `void el.offsetWidth` для перезапуска анимации
(reflow; у нас ретриггер `.bump` без него), `border-width` в `@keyframes` (paint каждый кадр),
бесконечные анимации (гард PERF-2 `test/css-infinite-composite.test.js`), ноль
`prefers-reduced-motion`, сырой hex/Tailwind, `navigator.vibrate` мимо `haptic()`.

**Зависимость: вся линия после MOTION-FIX.** Там записывается секция Motion в
`.claude/rules/design.md` (закон кадра) и гард на конечные `transition` с layout-свойствами.
Без них новые эффекты снова судятся текстом промпта и дрейфуют вместе с чекаутом.

### RAIL-1 — рейка-оглавление на Статистике (вне линии)

**Факт.** Идея Gio 24.09: вместо голой прокрутки — лесенка штрихов у правого края, как оглавление
глав в Claude. Штрих = секция, активный длиннее и в акценте. Тап по штриху или протяжка пальцем
ведёт в секцию. Мокапы «было / A / B» показаны 24.09, **выбран B**: рейка проявляется на
скролле и гаснет через 1.5 с тишины (как индикатор прокрутки iOS). Вариант A (всегда на виду)
отклонён: на экране графиков штрихи лежат поверх 1ПМ и календаря.

Опора в коде. `.screen` — сам себе скроллер (`position:absolute; inset:0; overflow-y:auto`
внутри `#screens`, `index.html:324-350`). Экраны прячутся через opacity, не display
(`js/dashboard.js:60`). Прецедент прыжка к секции — трекер камер острова
(`js/shared/dynamic-island.js:253`).

**ЦЕЛЬ.** Общий компонент `js/ui/section-rail.js`: `mountSectionRail(screenEl)` → `destroy()`.
Пилот — Статистика за флагом `'section-rail': false` (`js/flags.js`, `flag()`). Модуль
грузится динамическим `import()` только при включённом флаге, легаси не трогаем.

Решено до кода:

- **Якоря — явная разметка `data-rail-label`**, не скрейп `.section-header`: у календаря
  заголовка секции нет. Шесть: Обзор (`#strength-hero` + чипы) · PPL · Сила · Календарь ·
  Неделя · 1ПМ. Пустое состояние (нет тренировок) — якорей ноль, рейка не монтируется.
- **Рейка — узел в `#screens`** (он не скроллится), `position:absolute` у правого края между
  клиренсами 72/120 px. Не `position:fixed` к окну (AIR п.5). Видна только на активном
  `s-stats` (`ap-nav-change`).
- **Активная секция — `IntersectionObserver` с `root = screenEl`** и узкой «линией активности»
  в `rootMargin`. Opacity-скрытие экрана ему не мешает: корень — сам экран.
- **Переживает ререндер.** `load()` пересобирает `innerHTML` (закон кадра п.6): якоря
  переснимаются, IO переподписывается, хост рейки не пересоздаётся.
- **Проявление (вариант B).** Скролл экрана → `opacity: 1`, таймер 1.5 с тишины → `opacity: 0`
  (`setTimeout`, не rAF-петля). На протяжке не гаснет. **Скрытая рейка — `pointer-events:
  none`.** В мокапе касание края будило рейку, в коде нет: невидимая зона 44 px молча съедала бы
  тапы у правого края — кнопку периода, значения 1ПМ. Будит только скролл.
- **Жест.** Pointer-события на рейке, зона попадания ≥44 px при штрихе ~22 px,
  `touch-action:none` только на рейке. Протяжка: Y → индекс чистой функцией `indexAtY`. На смене
  индекса — тик через Haptic Gate (`js/shared/utils.js`) и подпись слева от пальца
  (`textContent`, не `innerHTML`). Отпустил → прыжок, тап → прыжок:
  `screenEl.scrollTo({top: anchor.offsetTop - 72})`, `behavior: 'auto'` при reduced-motion.
- **Движение.** Штрихи только `transform: scaleX` + `opacity`, токены `--t-*`/`--ease-*`, без
  вечных `@keyframes`, гашение глобальным reduced-motion.
- **Пузырь подписи без blur:** `--c-bg-2` + `var(--c-border-h)`. Стекло — только селектором в
  `TIER2_WHITELIST` **и** `TIER2_REQUIRED` (`test/air-guard.test.js`), как делал HUD-1.
- **Доступность:** `<nav aria-label>`, штрихи — кнопки с `aria-label` секции.

**ГДЕ СТОП.** На Android с включённым флагом рейка проявляется на скролле и гаснет. Тап и
протяжка ведут в нужную секцию, активный штрих идёт за скроллом. С выключенным флагом экран
тот же, что до карточки.

**ФАЙЛЫ.** `js/ui/section-rail.js` (новый) · `js/analytics.view.js` (6 × `data-rail-label` +
монтаж) · `js/flags.js` · CSS рейки в `css/base.css` (общий компонент не кладётся в лениво
грузимый CSS экрана) · i18n «Обзор» / «Календарь» · `js/version.js` + `package.json` + lock ·
`sw.js` через `npm run build:sw`.

**ГЕЙТ.** `npm test` + `test/section-rail.test.js` (`indexAtY`, выбор активного). E2E
`test/e2e/section-rail.spec.js`: сид IDB, флаг on; скролл → рейка видна, активный штрих
сменился; тап → `scrollTop` сменился; 1.5 с тишины → рейка погасла и не ловит тап у края.
Chromium + webkit: `touch-action` в WebKit ведёт себя иначе. Зелёные `design-tokens`,
`air-guard`, `finite-transition-layout`, `css-infinite-composite`.

**Поле, Android — главный риск.** Жестовая навигация: свайп от правого края = «назад», а веб
не может исключить зону, как нативный `setSystemGestureExclusionRects`. Протяжка вертикальная,
но дрожь по горизонтали у самого края может увести назад. Прогнать на жестовой навигации;
увело — отодвинуть зону попадания от края, а не расширять.

**НЕ ТРОГАТЬ.** Таб-бар (закон четырёх вкладок): рейка не вкладка и не вход в экран. Переход
`.screen` в `index.html`. Главную и Core — их файлы правит линия CORE. Трекер камер острова.
**Очередь:** после полевого захода MO-2/MO-2b в Stats. Тот же экран: два изменения в одном
поле не различить.

### MO-3 — проявление списков на скролле

**ЦЕЛЬ.** `animation-timeline: view()` на карточках длинных списков: прошлые сессии, журнал,
история замеров. Ноль JS, ноль `IntersectionObserver`, анимация живёт вне main thread.

**ГДЕ СТОП.** Список журнала на 100+ записях проявляется при скролле, кадры не проседают на
телефоне (профиль — дельта к baseline, не абсолют). `prefers-reduced-motion` гасит.

**ФАЙЛЫ.** `css/base.css` (общий класс), `css/journal.css`, `css/workout.css`.

**ГЕЙТ.** `npm test` · полевой скролл на телефоне · бамп версии · `build:sw`.

**НЕ ТРОГАТЬ.** `IntersectionObserver` в `js/journal.view.js:166` — он про ленивую подгрузку,
не про анимацию; снимать его нельзя. Train live и rest-бар — там скролл во время подхода.
Карточки, которые перерисовываются рендером, — урок «анимация мертва, если хост пересоздаётся».

### MO-4 — числа набегают

**ЦЕЛЬ.** `Spring.animate` (`js/shared/spring.js`, уже используется в трёх местах) на числа
холодных экранов: BMI и веса в Профиле, тоннаж и объём в Аналитике, итоги Сводки.

**Ограничители — часть цели, не пожелание.** Только `font-variant-numeric: tabular-nums`
(в CSS уже везде) — иначе ширина прыгает и каждый кадр стоит layout, а не paint. Потолок:
≤6 чисел на экран, ≤600 мс, один общий rAF на экран, а не по таймеру на число.

**ГДЕ СТОП.** Профиль открывается — числа набегают и садятся; повторный вход на тот же экран
не перезапускает анимацию. Дельта кадров к baseline на телефоне неотрицательная.

**ФАЙЛЫ.** `js/shared/spring.js` (хелпер-обёртка), `js/profile.view/`, `js/analytics.view.js`.

**НЕ ТРОГАТЬ.** Train live, rest-таймер, остров, вес в барабане — там число это ввод, а не
результат; «показано ≠ записано» уже стоило карточки. Дашборд-бары — Spring там свой.

### MO-5 — плитка разворачивается в экран

**ЦЕЛЬ.** Shared-element переход: `view-transition-name` на `.type-card[data-type]`
(`css/workout.css:29`) и на шапке экрана тренировки. Жмёшь PUSH — плитка физически
разворачивается в экран, а не растворяется вместе со всем остальным.

**ГДЕ СТОП.** Переход читается как «вошёл внутрь плитки». Быстрая серия тапов по таб-бару не
роняет навигацию и не рассинхронизирует `.out`/`.active` — очередь `_transitionQueue`
(`js/shell.js:95`) держит. На движке без shared-element остаётся нынешний crossfade.

**ФАЙЛЫ.** `css/workout.css`, `css/base.css` (правила `::view-transition-group`), `js/shell.js`.

**ГЕЙТ.** `npm test` · `npx playwright test` · полевой прогон: серия из 10 быстрых тапов по
четырём вкладкам · бамп версии · `build:sw`.

**НЕ ТРОГАТЬ.** `performNav` и порядок `.out`/`.active` — «Nav.go теряет тап в быстрой серии»
уже покупалось кровью. Закон четырёх вкладок: экран тренировки не становится пятой.
`_swallowSkippedTransition` — он гасит ожидаемый шум, не ошибки.

### FRAME-1 — замер кадров в рантайме (первой во второй волне)

**Почему.** «Плавно» сейчас — ощущение на телефоне плюс lhci, а lhci меряет загрузку, не
анимации. В коде ноль `PerformanceObserver('longtask')` и ноль счётчика кадров. Каждая карточка
линии принимается по «дельта к baseline», а baseline снять нечем.

**ЦЕЛЬ.** Debug-модуль за флагом (дефолт OFF): p95 и p99 длительности кадра, % пропущенных,
long tasks > 50 мс, экспорт JSON. Один `rAF`-цикл только пока флаг включён. Приём —
`meterLoop` из `tonnage_motion_wow.html`, без подписи «120 Гц», угаданной по p95.

**ГДЕ СТОП.** Цифры экрана тренировки сняты на телефоне Gio через `chrome://inspect` и записаны
сюда baseline-ом. Скрытое превью как источник цифр не годится — rAF там мёртв.

**НЕ ТРОГАТЬ.** Прод-путь: при флаге OFF модуль не импортируется.

### RANK-1 — стандарты силы по тапу на бейдж «Мастер жима»

**Факт.** Движок есть и честнее прототипного: `exrxTier()` (`js/strength-engine.js:142`) —
пол, вес, возраст, процентиль. Бейдж `push_master` (`js/shared/athlete-room.js:118`) выдаётся
за **10 жимовых тренировок**, не за силу: тап «Мастер жима» → «ты Novice» — противоречие в
одном экране, если его не развести.

**ЦЕЛЬ.** Тап на бейдж → шторка на `.sd-overlay`: сверху — как получен бейдж (10 тренировок),
ниже — лестница уровней жима в **кг под вес пользователя**, текущий уровень, «+X кг до
следующего». Всё из `exrxTier`, e1RM — из существующего расчёта. Иконки уровней — SVG.

**ГДЕ СТОП.** Мужчина и женщина одного веса видят разные пороги (тест на шторку через
`exrxTier`); без веса тела — просьба заполнить профиль, а не выдуманный дефолт 80 кг.

**НЕ ТРОГАТЬ.** Формулу прототипа, условие выдачи бейджа, подписи «IPF» / «Топ 5%» без
источника. Радар силы уже есть — второй не строить.

### HOLD-SAVE — замок сохранения тренировки

**Где и почему только там.** Удержание — трение. На отметке подхода (20–30 раз за тренировку)
оно надоест за неделю. Кнопка «Сохранить» в итоговой модалке — одна на тренировку, финал
сессии: ей положен эффект. Приём — `tonnage_motion_wow.html` § 02.

**ЦЕЛЬ.** Удержание ~700 мс: кольцо набора, тики `haptic()` на 25/50/75 %, отпустил раньше —
откат с затуханием (`js/shared/spring.js`), на 100 % — имплозия кнопки, ударная волна, дельта
тоннажа улетает в счётчик (MO-4). Волна — `transform: scale` + `opacity`, без `border-width`;
кольцо — `transform` полуколец, не `stroke-dashoffset`/`@property` (фильтр линии их отклонил),
пока FRAME-1 не покажет обратное.

**ГДЕ СТОП.** Одно удержание = ровно одно сохранение (защита `_executeFinalSave` не тронута);
скринридер, клавиатура и reduced-motion — обычный тап; p95 в норме по FRAME-1.

**НЕ ТРОГАТЬ.** Отметку подхода, `_executeFinalSave`, `cancelSession` (там `confirmDialog`).

### RPE-HEAT — накал отказа

**Факт.** RPE сейчас — ряд кнопок, один тап, повторный снимает (`js/workout.view/handlers.js:182`),
шкала целая. Правило Gio: «RPE — один тап, ноль обязательных». Тахометр прототипа — слайдер,
то есть новый ввод; в этом виде отклонён.

**ЦЕЛЬ.** Эффект без нового ввода: тап RPE 9–10 → активная кнопка «накаляется» (слой на
`opacity` с токеном `--c-bad`), одна дрожь ≤ 240 мс на `transform`, двойной импульс `haptic()`.
Второй шаг, по мокапу «было / A / B»: мини-тахометр **только для чтения** — средний RPE в
итоге тренировки.

**ГДЕ СТОП.** Ввод как был, один тап; эффект конечный; reduced-motion — только цвет.

**НЕ ТРОГАТЬ.** Модель данных RPE, шкалу, `setRPE` кроме класса эффекта.

## Что считать провалом линии

Любая карточка, после которой на живом телефоне кадры просели против baseline, откатывается
целиком — эффект не торгуется против плавности. Baseline снимать **до** правки и на тех же
данных: без сида IDB измерение фикция.
