> но обе — после `CORE-5` и до `CORE-7`.

## Почему в этом порядке

Каждая следующая карточка стоит на артефакте предыдущей: `CORE-6` красит снимок,
которого нет без `CORE-4`; `CORE-7` режет промпт, который сперва должен стать снимком,
а не сырыми записями; `CORE-9` меряет качество ответов, которые к этому моменту уже
идут по новому контракту. Сборка в обратном порядке — тот же класс дефекта, что
отвергнутая линия «phase 8» (`docs/_archive/HANDOFF_intel_readiness.md`): второй путь
данных мимо уже работающего.

## CORE-6 — UI считает движок, модель объясняет [поглощает `INTEL-3`/`INTEL-4`]

> Абсорбирует незаведённую линию `INTEL-3` (виджет готовности на `fetchReadiness()`) и
> `INTEL-4` (контракт `_widget`, кнопки) — обе описаны в
> `docs/_archive/HANDOFF_intel_readiness.md`, там же помечены поглощёнными.

**ЦЕЛЬ.** Все числа в UI ядра — только из локальных движков (`intel.engine.js` и
соседей), не из ответа модели. Модель отвечает текстом, не JSON-виджетом с цифрами.

**Что убирается (решение Gio, метрика без источника данных):**

- Виджет готовности переезжает на `fetchReadiness()` (`INTEL-3`) — сейчас рисуется по
  `_widget: readiness` из потока модели, разные числа от запроса к запросу.
- «Качество сна» — вон целиком, данных о сне в БД нет и не будет.
- `density` — не рисуется дважды (`js/intel.view.js:835-836`).
- `muscleDamage` → усталость по мышцам как тепловая карта (тот же движок, другая форма
  подачи — не медицинский термин).
- Недельный score — считается локально, не запрашивается у модели.
- Радар-«театр» (визуал без данных под ним) — снимается.
- Модуль получает немедицинское имя (текущее рабочее — не публиковать без решения Gio).

**Контракт кнопок (`INTEL-4`):** `analyzeStats()`/`checkBiometrics()` перестают ждать
от модели JSON с цифрами — контракт `_widget` в `js/shared/air-markdown.js` и его гард
`test/intel-markdown.test.js` переписываются под «текст от модели, цифры от движка».

**Язык ответа = язык UI** (решение Gio, п. 6): `isRu()`, не наличие кириллицы в вопросе;
строки дверей — через `t()`, не хардкод. Промпт требует «SPEAK RUSSIAN ALWAYS»
(`routes/coach.js:471`) безусловно — это тоже сюда.

**ГДЕ СТОП.** `CHANGELOG.md:1457` перестаёт врать про `fetchReadiness()` — вызовы
реальны и покрыты тестом. Ни один экран ядра не красит число, которого нет в снимке
`CORE-4`. `test/intel-readiness.test.js` (44 кейса) и новый гард на состав виджета —
зелёные.

**НЕ ТРОГАТЬ.** Формулы движка (`WEIGHTS`, `CNS`, окна ACWR) — калибровка `INTEL-2b`
закрыта, не переоткрывать без решения Gio. Промпт-инструкции вне языка ответа — `CORE-7`.

## CORE-8 — airgap/ИИ выключен — полноценный локальный режим

**ЦЕЛЬ.** Отключённый ИИ (airgap или тумблер) — не ошибка и не 503, а осознанный режим:
снимок движков (`CORE-4`) + шаблонные инсайты без похода к модели.

Быстрый UI-сигнал (плашка «Локальный режим») уже ставится раньше, в `CORE-S` —
`CORE-8` строит сам режим: шаблонные тексты вместо инсайтов модели, а не только
баннер поверх пустого экрана.

**ГДЕ СТОП.** При выключенном ИИ экран ядра показывает снимок и шаблонные инсайты,
ни одного сетевого вызова к модели, ни одной ошибки в консоли. Тест: airgap ON →
рендер без fetch к `/api/coach`.

**НЕ ТРОГАТЬ.** Сам движок расчёта (`CORE-4`/`CORE-6`) — здесь только путь без модели.

**НЕ ТРОГАТЬ.** Транспорт SSE и `compression` — это `CORE-3`, уже отдельная карточка
в `CORE-S`.

релизом ядра после `CORE-6`/`CORE-7`.
