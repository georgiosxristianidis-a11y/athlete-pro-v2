## Что сказало поле

Три наблюдения Gio, каждое проверено по коду — формулировки ниже исправлены там,
где поле описывало симптом, а код показывал другую причину.

| Наблюдение Gio                                      | Что нашлось в коде                                                                         | Карточка  |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------ | --------- |
| «Внимание рассеяно, не хватает воздуха, увеличить на 5-10%» | Focus Mode написан и **намеренно заглушен** (`f82bc258`): разметка есть, CSS нет            | `FIELD-4` |
| «Тренажёр занят / упражнения нет в зале — оно мешает» | В меню упражнения ровно три действия, пропуска нет                                          | `FIELD-1` |
| «Пауза 2 месяца — в статистике не видно?»            | Не видно. И хуже: автопрогресс **не смотрит на дату** и предлагает июльский вес или +шаг     | `FIELD-2`, `FIELD-3` |

Попутно вскрылся долг, который подпирает две карточки из трёх: прогрессия живёт в
**трёх несогласованных местах** — `FIELD-5`.

### FIELD-1 — пропуск упражнения в текущей сессии

**ЦЕЛЬ.** Дать выход из ситуации «тренажёр занят» без правки плана: упражнение
уходит вниз списка, гаснет, его сеты не читаются ни как выполненные, ни как
провал; повторный тап возвращает на место. Живёт ровно одну сессию — в следующей
тренировке упражнение на своём месте с прежним весом.

**ГДЕ СТОП.** В меню упражнения (три точки) появился четвёртый пункт «Пропустить
сегодня». Пропущенная карточка визуально погашена и стоит ниже активных.
Возврат — один тап, без захода в меню. Перезагрузка страницы статус не теряет
(`persistSession`). Недельная нагрузка и ACWR от пропуска не проваливаются.
`npm test` зелёный, включая гард на новый статус в модели сессии.

**НЕ ТРОГАТЬ.** Номер упражнения в круге — рядом стоит хват перетаскивания, два
жеста в сорока пикселях друг от друга дадут промахи потной рукой; к тому же
номер означает порядок, второй смысл на нём читаться не будет. Длинное нажатие
по шапке карточки — зарезервировано за `FIELD-4`. `openReplaceExModal` — замена
это другое намерение, не смешивать с пропуском.

#### Что вскрылось

| Находка                                                                                                       | Где                                    |
| -------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| Меню упражнения несёт три действия: Заменить · Гантели · Копировать. Пропуска нет                              | `js/workout.view/handlers.js` — `showExerciseMenu` |
| В модели сета есть только `done` — третьего состояния «пропущено» не существует                                | `js/workout.store.js` — `buildSession` |
| Нагрузка сессии считает сеты с `done !== false`; пропуск молча уронит недельный тоннаж и потянет вниз ACWR      | `js/intel.engine.js` — `sessionLoad`   |
| Порядок упражнений уже перетаскиваемый — «вниз списка» ложится на существующую механику, новой модели не нужно | `js/workout.view/render.js` — хват `⠿` |

#### Ловушки

- **Пропуск не равен провалу.** Если пропущенное упражнение просто останется с
  нулём закрытых сетов, статистика покажет спад там, где был занят тренажёр.
  Нужен явный статус, а не «ноль сетов».
- **Undo обязателен.** Действие ощущается деструктивным (карточка исчезает из
  поля зрения) — возврат одним тапом, иначе это ловушка для промаха.
- **Второе намерение не закрывается этой карточкой.** «В зале нет hip thrust,
  не предлагай вообще» живёт в плане, а не в сессии. Это профиль оборудования
  зала — отдельная крупная фича (так решает Fitbod), заводить отдельно.
- Регулярный пропуск отравляет префилл: следующая сессия возьмёт вес из
  последней, где упражнение делалось. Стыкуется с `FIELD-2` — там же и лечится.

### FIELD-2 — автопрогресс обязан смотреть на дату

**ЦЕЛЬ.** Убрать вредный совет после перерыва. Сейчас предложение веса строится
по последней сессии с этим упражнением **без всякой проверки давности**: если
тогда были взяты целевые повторы, приложение предложит тот вес плюс шаг. После
двух месяцев простоя это встречает вернувшегося июльским рабочим весом.
Ввести возраст записи: старше порога — не бампать, предложить сниженный вес и
сказать об этом словами.

**ГДЕ СТОП.** Тест воспроизводит полевой случай: история двухмесячной давности с
взятой целью даёт вес **ниже** прежнего, а не выше. Предложенный вес лежит на
сетке упражнения (`weightStep`). В карточке упражнения видна причина — «8 недель
перерыва, начинаем мягче», без формулировки-обвинения. Baseline красный на коде
до фикса.

**НЕ ТРОГАТЬ.** Сетку весов — любой результат обязан пройти `snapWeight` с шагом
упражнения, иначе вернётся `BUG-DRUM-OFFGRID` («показано ≠ записано»), см.
`test/weight-grid.test.js`. Закрытые сеты — это факт тренировки. Пороги данных
в intel-движке (`MIN_DATA`): они куплены калибровкой и решают другую задачу.

#### Что вскрылось

| Находка                                                                                                     | Где                                          |
| ------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| Предложение веса не читает `timestamp` вообще — ни ограничения давности, ни коэффициента                      | `js/workout.store.js` — `_smartNextWeight`   |
| Поиск последней сессии по имени тоже без порога давности: «последняя» может быть годовой                      | `js/workout.store.js` — `latestWorkoutForNames` |
| Intel-движок после паузы **молчит**: ACWR не считается, пока в 28-дневном окне меньше четырёх сессий          | `js/intel.engine.js` — `MIN_DATA`            |
| Детектор плато считает сессии подряд, календарь не смотрит — три сессии за полгода он назовёт плато            | `js/progressive-overload.js` — `detectPlateau` |

#### Развилка для Gio

Порог и глубина снижения — **решение Gio, не агента**. Отправная точка для
разговора: перерыв от 3-4 недель отключает бамп, от 6 недель предлагает около
80% прежнего рабочего. Физиология даёт ориентир — за 8 недель тренированный
теряет порядка 5-15% силы, возврат занимает 2-4 недели, — но личный порог
калибруется на своих данных, а их пока мало.

#### Ловушки

- **Тон решает.** «Ты не тренировался 2 месяца» — обвинение; «возвращаемся,
  первая неделя на 80%» — то же число в рабочей рамке.
- **Не ломать историю PR.** Снижение после паузы не должно читаться в графиках
  как регресс — иначе честное поведение выглядит провалом.
- Автоматический многонедельный протокол возвращения **в эту карточку не
  входит**: это тренерская логика, её легко сделать неверно и демотивировать.

### FIELD-3 — перерыв виден на графиках

**ЦЕЛЬ.** Разрыв в тренировках должен читаться с экрана. Сейчас кривые силы
строят X по реальному времени и соединяют точки сплошной линией — двухмесячная
пауза выглядит как обычный длинный отрезок.

**ГДЕ СТОП.** Разрыв больше 21 дня рисуется иначе, чем рабочий промежуток
(пунктир или разрыв заливки), рядом читается длительность паузы. Скраб по
кривой на разрыве не врёт. `npm test` зелёный.

**НЕ ТРОГАТЬ.** `valueBand` — подбор диапазона куплен отдельно, «чтобы подъём на
2 кг не выглядел обрывом». PPL-цвета берутся только через `pplColor`, сырой хекс
рядом со словом push/pull/legs красит гейт.

#### Что вскрылось

| Находка                                                                                | Где                                  |
| ---------------------------------------------------------------------------------------- | ------------------------------------ |
| X считается как доля от общего диапазона времени, линия сглаживается и соединяет всё подряд | `js/analytics.strength-curves.js` — `curveCard`, `smoothPath` |
| Точки подписаны месяцем — по подписи пауза угадывается, но глазом не видна                 | `js/analytics.strength-curves.js` — `fmtMon` |

### FIELD-4 — фокус в set logger: сперва мокапы, код потом

**ЦЕЛЬ.** Выбрать направление, а не начать писать. Поле просит «больше воздуха и
чуть крупнее», но запрос про размер — симптом: на экране одновременно около
шестидесяти интерактивных целей, и время визуального поиска растёт от их числа,
а не от кегля. Плюс 5-10% ниже порога заметности и не окупит перерисовку.
Показать Gio три состояния в натуральную величину (375×812) и получить решение
строкой.

**ГДЕ СТОП.** Gio выбрал вариант и записал решение. Код в этой карточке **не
трогается** — ни CSS, ни разметка.

**НЕ ТРОГАТЬ.** Ранний `return` в `_initFocusLongPress` остаётся на месте до
решения — он там намеренно. Барабаны веса и повторов.

#### Варианты на мокап

| Вариант                | Суть                                                                                  | Цена и риск                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **Как сейчас**         | Все упражнения развёрнуты                                                             | Ноль                                                                          |
| **A — раскрытие в списке** (рекомендую) | Активное упражнение крупнее на 25-30%, остальные — строка «название · 3/3 · 20 кг» | CSS плюс флаг, обратимо; механика автосворачивания уже есть в `toggleSet`     |
| **B — полноэкранный фокус** | Оживить Focus Mode: одно упражнение на весь экран                                  | CSS с нуля; отрезает обзор «сколько осталось»; новая поверхность для багов    |

#### Что вскрылось

Focus Mode **уже написан**: `renderFocusMode` рисует полноэкранный режим с одним
упражнением, `_openFocus` работает, вход по длинному нажатию существует. Но
`_initFocusLongPress` начинается с `return` — коммит `f82bc258` (`quarantine Focus
Mode long-press`): оверлей уезжал за пределы мобильной колонки, потому что под
`.focus-overlay` и соседей **не написано ни строчки CSS**. Код оставлен под
однострочный возврат «когда фича будет нарисована». То есть вариант B — не
стройка с нуля, а достройка карантина.

#### Ловушки

- **Скрытый барабан — исторический источник «0 кг».** `display:none` обнуляет
  `scrollTop`, браузер его не возвращает; там уже стоят три гарда (`dirty`,
  `clientHeight`, heal через ResizeObserver). Любой режим, который прячет или
  пересоздаёт барабаны, обязан пройти `test/drum-picker.test.js` и
  `test/drum-contract.test.js` целиком.
- **Два контекста одного экрана.** В зале нужен фокус, дома при планировании —
  обзор. Это развилка «режим или раскрытие», и решать её надо до кода.
- Полноэкранный фокус забирает индикатор прогресса тренировки — в зале это
  половина мотивации. Вариант B обязан нести свой прогресс.
- Тач-цели не меньше 48 пикселей: потная рука, тремор после подхода.

### FIELD-5 — прогрессия из трёх источников в один

**ЦЕЛЬ.** Свести три несогласованные реализации прогрессии к одной. Пока их три,
любая работа по `FIELD-2` строится на песке: дашборд советует одно, автопрогресс
пишет другое, третий движок не подключён никуда.

**ГДЕ СТОП.** Один источник правды. Число, которое показывает дашборд, совпадает
с тем, что автопрогресс подставит в сессию — это проверяет тест, а не глаз.
Судьба неподключённого движка решена явно: подключён или снесён, «пусть лежит»
не ответ.

**НЕ ТРОГАТЬ.** Сетку весов (`weightStep` / `snapWeight`) — результат любой
формулы обязан лежать на узле. Не сносить `progressive-overload.js` без решения
Gio: там живёт детектор плато и деload, которых больше нигде нет.

#### Что вскрылось

| Источник                                          | Что делает                                    | Статус                                  |
| -------------------------------------------------- | --------------------------------------------- | --------------------------------------- |
| `js/workout.store.js` — `_smartNextWeight`        | Реально пишет вес в сессию                    | Живой, правился 2026-09-17              |
| `js/progressive-overload.js`                      | Плато, деload, инкременты по типу упражнения  | **Не подключён к UI** — около 350 строк |
| `js/claude.store.js` — `_computeSimpleProgression` | Рекомендация на дашборде                      | Живой, и с ошибкой                      |

Ошибка в третьем: `Math.round(lastWeight * 2 + 2.5) / 2` по приоритету операций
даёт **+1.25 кг**, хотя комментарий рядом обещает +2.5. Дашборд показывает не то
число, которое подставит автопрогресс.

## Почему такой порядок

**`FIELD-1` первой** — дёшево, обратимо, снимает ежедневное раздражение и ничего
не ломает: один пункт в существующем меню.

**`FIELD-2` второй** — это не косметика. Сегодня приложение даёт неверный вес
после паузы, и Gio правит его руками в зале прямо сейчас.

**`FIELD-4` третьей, и только мокапами** — самая дорогая и самая спорная задача
из трёх. Решать её по описанию словами — верный способ сделать красиво и
неудобно.

**`FIELD-3` четвёртой** — полезно, но это чтение данных, а не поведение.

**`FIELD-5` последней** — уборка. Берётся отдельно от `FIELD-2`, но подряд с ней:
обе трогают предложение веса, параллельно их брать нельзя.
