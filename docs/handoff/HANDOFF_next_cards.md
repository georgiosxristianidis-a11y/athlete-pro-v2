## Разбор PROF-1 (1.25.35) — что именно оказалось мёртвым

**Кнопка бэкапа.** Висела отдельной картой между паспортом и настройками (`profile.js`) и дублировала «Экспорт JSON» в секции DATA — одно действие `settings:exportData` в двух местах одного экрана. Переехала в DATA как главная кнопка с подписью «последний бэкап»; одно-тапность (GYM-GRADE DoD-5) сохранена, мелкий дубль «Экспорт JSON» убран. Секция теперь читается по логике: **облако → копия → обслуживание**, дедупликация отделена от бэкапа (она чинит базу, а не спасает данные наружу).

**Три настройки удалены как мёртвые** — проверено грепом по всем потребителям:

| Настройка | Куда писала | Кто читал |
|---|---|---|
| Режим тренировок | `training-mode` | никто (только подсветка самой кнопки) |
| Длина сессии | `session-time` | никто |
| Ограничения | `limitations` | никто — а профиль читал вообще другой ключ, `coach.injuries` |

AI-коуч отправляет только имя, возраст, пол и цель (`claude.store.js:448`), рядом лежит заглушка `longTermStats = {}` с пометкой «Phase 7». То есть UI обещал влияние на советы, которого не существовало ни в одном месте кода. У «Ограничений» вдобавок расходились ключи записи и чтения — введённый текст не вернулся бы даже в свой же профиль.

Ключи в IndexedDB **не удаляются** — старые бэкапы должны импортироваться без потерь. Удалён только UI и обработчики. Вернуть — когда коуч начнёт их читать; тогда же чинить ключ `limitations` → `coach.injuries`.

Заодно убран `toggleReminder` — экспортированный обработчик, который ни один элемент UI не вызывал (замечено ещё в PP-6, числился отдельной мелкой карточкой).

**Ловушка сессии:** комментарий, объясняющий удаление, был вставлен внутрь шаблонной строки — и обратные кавычки вокруг имён ключей закрыли литерал. Экран рендерился пустым, в консоли `SyntaxError: Unexpected identifier 'limitations'`. Внутри `` ` ``-шаблона обратные кавычки в комментариях запрещены так же, как в коде.
