> Замер: `npm run tokens` (`scripts/token-economy.mjs`, источник — транскрипты Claude Code).
> **Цифры здесь — базовая линия на 2026-08-18, не истина.** Перед взятием карточки перемерить.

**Порядок:** TOK-8 закрыта → **TOK-1** (самая крупная статья) → TOK-6 (две строки, эффект

TOK-9 и TOK-10 берутся отдельно: TOK-9 кода не трогает, TOK-10 требует интерактивной сессии

**TOK-8 закрыта (2026-08-19, PR#221, `9b6488a` в main).** Оценщик занижал 24-36%, потому что
markdown-разметка и пути шли по ставке латинской прозы (3.5 симв/ток). Латиница разделена на
«буквы+пробелы» (÷3.5, ставка сохранена) и `structural` — пунктуация/цифры/пути (÷1); обе
калибровочные точки бьются в пределах ~2%. Ветка `structural` покрыта юнит-тестом
(`test/docs-budget.test.js`) — на целых файлах она неотделима от остальных, и подгонка
коэффициента без такого теста ничем не сторожится.
**Прямая калибровка обоих делителей (кир≈2.1, лат≈2.0) — тупик, не повторять:** решает систему
по двум точкам идеально, но делает латиницу дороже кириллицы на чистом тексте, то есть
переносит специфику markdown на язык и валит инвариант «кириллица вдвое дороже».
Откалиброванный гейт закономерно покраснел (6356/5000) — доки резались тем же PR до
2936+1858=4794/5000; решение «резать, а не поднимать потолок» принято Gio явно.
Остаток — **TOK-10** (третья точка): пока её нет, формула проверена только на том жанре текста,
на котором настроена.

## Опровергнуто перепроверкой 2026-08-18 (было в этом файле как факт)

Две формулировки первой редакции не пережили разбор. Оставлять их нельзя: следующая
сессия берёт хендофф за факт — на этом и держится вся его польза.

- **«Сессии-марафоны»: 17 сессий >24ч работали 24 часа.** Неправда. Часы здесь
  астрономические — это открытая вкладка, а не работа; активной работы в них ~7% от
  длительности. Отсюда и правка TOK-1: порог по числу вызовов, время в гард не берём.
  Ярлык живёт не только здесь — `npm run tokens` печатает `<- сессии-марафоны`
  (`scripts/token-economy.mjs:186`).
- **«Холодный старт = 9k ток доков + повторная разведка» как причина цены одноразовых
  ворктри.** Причинность не доказана. Известен только факт: одноразовые дороже за вызов
  (0,1898 против 0,1094). Объяснение через длину сессии — такая же непроверенная
  гипотеза, и подставлять её вместо прежней смысла нет. Скрипт печатает
  `— цена холодного старта` (`scripts/token-economy.mjs:193`) — тот же тезис в терминале.

**Провенанс новых чисел — разный, и это важно.**

- **Воспроизводится сейчас, делением из вывода `npm run tokens` § СЕССИИ:** цена вызова
  по бакетам. $598 / (85 сес × 93 выз) = **$0,0756** у часовых против
  $2129 / (17 × 505) = **$0,2480** у открытых дольше суток. Ровно те же 3,3×.
  Скрипт печатает оба операнда, но не частное — **сложить `$/вызов` в вывод** первой же
  правкой TOK-1, чтобы следующий не считал руками.
- **Не воспроизводится:** 7% активного времени и корреляции r=0,81 (вызовы) против
  r=0,53 (время) — разовый разбор транскриптов, скрипт таких величин не считает.
  Направление они задают, но **порогом гарда служить не могут** (см. TOK-1: сперва
  наблюдение, потом число).
- Одноразовые ворктри 0,1898 против 0,1094 за вызов — тоже не воспроизводится: скрипт
  не разбивает вызовы по ворктри.

Числа плывут между прогонами: скрипт видит и текущую сессию (в прогоне 2026-08-18 после
правки — 42,6% и 64 одноразовых против 42,9% и 65 в таблице выше). Это ожидаемо, см. § Ловушки.

## Допущения, которые надо атаковать (не находки)

- **«10 токенов на строку кода»** → отсюда оценка «выход к осевшему коду 44:1». Порядок устойчив, точность нет.
- **Связь `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE: 50` с 32,6% на cache-write не доказана** — только кандидат на A/B. В TOK-6 это эксперимент, не диагноз.
- Деньги — list-цена по прайсу Anthropic, **не счёт**: подписка списывает иначе. Метрика для сравнения операций между собой.

## Ловушки

- **Оценщик `check-docs-budget.mjs` — оценка, а не измерение.** После TOK-8 он бьёт факт
  в пределах ~2% на двух точках, но обе — двуязычный markdown с таблицами и путями.
  На другом жанре (чистая английская проза, файл с плотными числами) поведение не проверено,
  см. **TOK-10**. Расхождение с `/context` больше ~5% — правится делитель, а не потолок.
- `npm run tokens` читает `~/.claude/projects` — **вне репо и вне git**. Цифры машинно-локальные: у другого агента на другой машине они свои.
- Скрипт видит и текущую сессию: два прогона подряд дают разные числа. Для дельты «до/после» мерить в одинаковой фазе.
- Замер по slug каталога. Ворктри проекта попадают автоматически, посторонний проект с похожим именем — тоже.
