## SW-CACHE — тёплый старт без сети (вне балла, про зал) — свободна

> Заведена 2026-10-07 по решению Gio, из разбора /devil внешнего роадмапа. Порядок линии
> («по цене для балла») на неё не распространяется: Lighthouse меряет холодный старт без SW
> и этот путь не видит, балл не сдвинется. Блокеров нет, PERF-9 не ждёт.

**Причина.** `networkFirst` (`sw.js:342`) на каждом открытии идёт в сеть за каждым JS/CSS/HTML,
а сервер отдаёт код с `no-cache` без валидаторов (`server.js:135`): 304 невозможен, тело всегда
полное. Бут-замыкание — 56 файлов, 260 КБ gzip (замер 07.10 по `ASSETS`). На слабом Wi-Fi в зале
каждый модуль ждёт сеть до таймаута браузера.

**ЦЕЛЬ.** Повторное открытие с живым SW не ходит в сеть за кодом: JS/CSS/HTML отдаются из
`CACHE_NAME`. Он уже атомарная версия — хеш манифеста (`scripts/build-sw.mjs:149`), хеши в именах
файлов и бандл для этого не нужны. Обновление штатное: новый `sw.js` → install →
`controllerchange` → reload, посреди тренировки отложен (`js/app.js`, `State.phase`).

**ГДЕ СТОП.**
1. **Baseline первым:** `node scripts/profile.mjs --net=3g --cpu=1`, секция «ПОВТОРНЫЙ ВИЗИТ».
   Baseline обязан показать запросы кода в сеть (≈56 на бут). Если `fromCache/total` не различает
   «SW из кеша» и «SW из сети» — сперва чинить метрику (счёт запросов на стороне сервера), иначе
   «после» нечем сравнить.
2. **Флаг `sw-cache-first`, по умолчанию OFF.** SW не видит `localStorage`: страница постит режим,
   как `privacy-mode` (`js/privacy.store.js:85`), SW хранит его на диске. **Грабли:** `activate`
   сносит все кеши, кроме `CACHE_NAME` (`sw.js:239`), — флаг в отдельном кеше обнулится на каждом
   деплое: исключить его ключ из чистки или держать в IDB. До первого сообщения — OFF, то есть
   поведение как сейчас.
3. **localhost / 127.0.0.1 — всегда network-first:** правка в dev видна без `build:sw`.
4. **Таймаут-гонку не делать** (совет «network-first + 1.5 с»): модуль A из сети, B из кеша в одной
   загрузке → `does not provide an export named`, белый экран.
5. **После:** тот же прогон, тот же seed, те же флаги — запросов кода ≈0. В `CHANGELOG.md` только
   дельта, абсолюты headless не публиковать (MEASURE-1 в `.claude/rules/architecture.md`).

**ФАЙЛЫ.** `sw.js` (руками только логика fetch/activate, списки — `npm run build:sw`),
`js/flags.js`, точка постинга флага рядом с `privacy-mode`, новый тест.

**ГЕЙТ.** `npm test` (`sw-two-phase`, `sw-cache-name`, `sw-digest`, `cache-headers` зелёные) +
e2e. Новый тест: флаг ON — код из кеша без `fetch`; OFF — как сейчас; localhost — network-first;
флаг переживает `activate`. Поле Gio (Android): слабый Wi-Fi — открытие до Home без ожидания сети;
деплой — обновление доезжает за один перезапуск. Только после поля — дефолт ON отдельным PR.

**НЕ ТРОГАТЬ.** Заголовки кода в `server.js` (`no-cache`/`no-store` — полевой случай 1.24.1,
сторож `test/cache-headers.test.js`). `mediaCacheFirst`. Ветку `/api/*` и airgap. Бандл и
хеширование имён (PERF-7 заморожена).

**Цена.** Обновление доезжает на запуск позже. Сломается путь обновления — пользователь залипнет на
старой версии; страховка — `forceUpdate()` (`js/shared/sw-update.js`) и `reg.update()` на `online`.
