## PERF-9 — LCP онбординга без водопада (диагноз переписан 22.11)

**Брать первой из открытых.** Прежний диагноз (FAB 62 px, `requestIdleCallback`) устарел —
см. замер 22.11: LCP холодного прогона — текст онбординга, ждёт ~1.28 с после FCP.

**ЦЕЛЬ.** `<p>` шага 1 онбординга рисуется без двух последовательных сетевых запросов после
бута: `onboarding.js` и `block-ticks.js` грузятся параллельно с бут-графом.

**Правка — A (рек.):** две строки `<link rel="modulepreload">` в `index.html` — на
`js/onboarding.js` и `js/shared/block-ticks.js` (Chrome не тянет зависимости modulepreload сам,
нужны обе). Ждём ≈−540 мс из FCP→LCP. Цена: +10 KiB на холодной загрузке у тех, кто онбординг
прошёл, и оба файла переедут из тёплого в бут-прекеш (`build:sw` строит бут по modulepreload;
потолок `test/sw-media-budget.test.js` 0.75 МиБ — сверить запас). B — ранний параллельный
`import()` обоих модулей в начале `js/app.js` за флагом `onboarding-early` (дефолт OFF):
по флагу откатывается, но стартует только после бут-графа — ≈−380 мс.

**Анимация — решено Gio 22.11: вариант A** (мокап «было / A / B» показан). Первый показ
оверлея (`showOnboarding` → первый `_render`, включая шаг, восстановленный из черновика) — без
`.animate-in`; переходы между шагами (`_obNext`/`_obPrev`) анимируются как сейчас. Ждём ≈−250 мс.
Отвергнуты: B (только `translateY`) — ~половина выигрыша; C (оставить fade) — 250 мс в LCP.

**ГДЕ СТОП.** (1) baseline: пробник `largest-contentful-paint` на холодном профиле указывает на
`<p>` онбординга и воспроизводит водопад `onboarding.js → block-ticks.js`; (2) после правки
`block-ticks.js` стартует не позже `onboarding.js`, оба — до конца бут-графа; дельта FCP→LCP
до/после в одной сессии (MEASURE-1); (3) первый показ шага без fade, переход шагов с fade. Балл на проде
(цель ≥98) — после деплоя, вне карточки. Остаток после правки — бут-цепочка ~220 мс и
eval+IDB ~150 мс: записать строкой, не чинить здесь.
**Мины:** если правка B — `import()` не должен поменять порядок `needsOnboarding → Dashboard.load`
(`js/app.js:342-354`). Возвращающийся пользователь (сид) видит главную, не онбординг — его LCP
мерить отдельно (`profile.mjs --seed`), чтобы правка его не ухудшила.

**ФАЙЛЫ.** `index.html` (A) или `js/app.js`+`js/flags.js` (B), `js/onboarding.js` (анимация,
вариант A), `sw.js` через `build:sw`, `test/perf-9-*.test.js`, версия. **ГЕЙТ.**
`npm run build:sw && npm test && npx eslint js/onboarding.js js/app.js`. **НЕ ТРОГАТЬ.**
Блокирующий CSS (`PERF-4`), постер и preload (PERF-1..3), порядок острова/athlete-room и
бут-цепочку `openDB → … → loadHapticPref` в `app.js`, `scripts/lighthouse.js`. Токены только
из `base.css :root`.

**PERF-9b — видео не на холодном старте (вне LCP, про вес).** `panda-voice.mp4` 321 KiB стартует
после LCP — балл не двигает, режет 43% байт. Прежний план в силе: флаг `panda-video-lazy`,
ленивый `src` в общем хелпере `panda-video.js` (FAB `claude.view.js:145` + пустой дашборд
`dashboard.js:368`), после подстановки перезапустить `play()` явно; ролик озвучен — превью muted.
