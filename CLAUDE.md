> Основной активный проект. Мультиагентная разработка: Claude Code + Gemini Pro + Antigravity.

## Multi-Agent Protocol

- **База — только `origin/main`.** Перед стартом: `git fetch origin && git checkout -b <ветка> origin/main`. Долгоживущий trunk упразднён (O-3).
- **Handoff между сессиями/агентами:** `NEXT_SESSION.md` в корне (правило GIO Context Integrity) — читать первым.
- Незакоммиченные диффы могут быть живым WIP другого агента — сверяйся с `NEXT_SESSION.md`, не откатывай вслепую.
- **Вывод инфраструктуры из эксплуатации = чеклист всех мест прошивки:** правила/доки · ветки и worktree · remote · настройки GitHub · Vercel. Закрыть три из четырёх = мина. Дефолт-ветку сторожит `preflight`.
- **Дрейф базы** сторожит `scripts/check-branch-drift.mjs` (pre-push + job `drift` в CI): блокирует пересечение по файлам, не отставание. Обход осознанный: `DRIFT_OK=1 git push`.
- **Вердикт «линию не вливать» = строка в `REJECTED_LINES`** (`scripts/rejected-lines.mjs`) тем же PR, что и сам вердикт. Якорь — SHA, не имя ветки. Гоняется в `preflight`, pre-push и CI. Обход осознанный: `DONOR_OK=1 git push`.
- **Правила и гарды, живущие в чекауте, дрейфуют вместе с чекаутом.** Протухший `CLAUDE.md` = протухшие правила. Единственный недрейфующий слой — CI и настройки GitHub, поэтому дубль гарда в CI обязателен. Агент ведёт себя странно → сперва `git log origin/main -- CLAUDE.md` и сверка его базы.
- **Зелёный гейт отвечает только на свой вопрос.** SCA — «нет уязвимостей», SAST — «стиль цел», тесты — «эта сюита прошла». Ни один не отвечает «код написан по сегодняшнему main». **Число в гейте сверять с базой:** зелёный на неполной сюите — не зелёный.
- **Ожидаемого кода нет на месте → `git log origin/main -- <файл>`, а не гипотеза.** «Странно, тут этого нет» почти всегда значит «влито в main, а у тебя старая база».
- **Аномалия в фоновом шуме — проговорить вслух, не игнорить:** спросить один раз или завести карточку.
- Разборы инцидентов, купивших эти правила, — `docs/_archive/INCIDENTS.md`. Здесь только правила: `CLAUDE.md` — поведенческий контракт, не журнал.
- Antigravity: `~/.gemini/antigravity/brain/<uuid>/`. Стандарты GIO: `~/.gemini/GEMINI.md` + `GEMINI.md` в корне. Аудиты — `/audit_core` · `/audit_cyber` · `/audit_speed`.

## Session Protocol (ассистент)

> Гайд для человека — `docs/RULES.md`. Здесь — что ассистент ОБЯЗАН делать каждую сессию.

- **Старт:** `npm run preflight` (ненулевой exit = чинить до работы; тот же гард стоит хуком — `docs/RULES.md`). Затем спросить «одна цель на сессию?»; расплывчато («по уму») → переспросить, не угадывать. Формат: ЦЕЛЬ / ГДЕ СТОП / НЕ ТРОГАТЬ.
- **В процессе:** напоминать «Коммит?» / «Чекпоинт?» после куска; длинно → чекпоинт + новая сессия ДО compact.
- **Финиш:** короткий хендофф (узкий файл под фазу, не god-object) + обновить память.
- **Verify-over-trust:** любое «готово» (вкл. Gemini) — гипотеза, пока gate-команда != 0. Показывать фактический вывод: нет лога — значит не выполнено, а фантазия.
- **Причина, потом ошибка:** сперва root cause, потом фикс — патч симптома вслепую всплывает тем же багом на следующем цикле.
- **Изоляция:** агенты пишут только в свой worktree; вливает только LEAD после гейта.
- **Влитие только через PR в `main`:** ветка от свежего `origin/main` → гейт → `gh pr create --base main` → зелёные чеки → `gh pr merge --rebase --delete-branch`. Отставание = сигнал: `git rebase origin/main` → перегнать гейт (в main могли приехать новые тесты) → снова PR. Вливать сразу, не копить.
- **Влитая ветка — не информация:** умирает в момент мёржа вместе со своим ворктри (`git worktree remove`). Тегом держим только отвергнутые линии.
- **«Влито» = ancestry, не слова:** `git merge-base --is-ancestor <sha> origin/main` вернул 0. Не «PR создан», не «ветка запушена». Для ревизии веток целиком — `npm run inventory` (сравнивает патчи: rebase-merge переписывает SHA, и ancestry врёт про давно выкаченное).
- **Рекомендация, не меню:** при выборе советовать лучший для проекта вариант + 1 строка «почему»; решает человек.
- Один разговор = одна цель; ресёрч — субагентом, в main только итог.

## Rules

> Конвенции, действующие в момент правки кода (Vanilla JS · `esc()` · закон четырёх вкладок ·
> Haptic Gate · `build:sw` · алиасы при миграции планов), — `.claude/rules/architecture.md`,
> грузится по путям. Здесь только процессное, действующее всегда.

- **Версия:** при каждом стабильном мёрже в main бампить `VERSION` в `js/version.js` + синхронно `version` в `package.json` и `package-lock.json` (проще всего `npm install`). Сторожит `test/version-sync.test.js`
- **Анти-хрупкость:** рискованный код — за флагом `js/flags.js` (Strangler-Fig); ветки < 24ч, от свежего `origin/main`; застрял → `git checkout .` и дроби. Дефолты флагов OFF; легаси не сносим — новый код рядом за флагом, переключаем по микро-элементу, коммитим зелёным. Перед крупным — тег `checkpoint-<date>`
- **Миграции — отдельным PR**, не мешать с фичами и рефакторингом.
- **Никогда не пушить в `main` напрямую** — только через PR, см. § Session Protocol.

## Tests

```bash
npm test                # node --test (unit + integration)
npx playwright test     # e2e (отдельно, не через node --test)
npm run smoke:prod      # доехал ли релиз до прода (DoD ступень 4); --wait 180 = поллить
```

**Счёт тестов не хардкодить — добывать командой.** Число в доке протухает от следующего теста и начинает врать про «устаревшую базу»:

```bash
git fetch origin -q
git diff --diff-filter=A --name-only HEAD origin/main -- test/   # пусто = сюита полная
```

Непусто = ветка не содержит части сюиты, зелёный прогон ничего не доказывает. Лечение — `git rebase origin/main` и перегнать гейт.
