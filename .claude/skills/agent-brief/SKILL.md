# Ритуал агента (копировать в бриф, не пересказывать)

> Агент не помнит правил между сессиями — значит ритуал живёт в брифе, а не в надежде на память. Шаблон ниже вставляется в задачу целиком.

```text
ЦЕЛЬ: <одна фраза, что должно работать после>
ГДЕ СТОП: <признак готовности, проверяемый глазами или командой>
ФАЙЛЫ: <globs, которые наряд открывает на запись; генерируемое сюда не пишут>
ГЕЙТ: <цепочка команд, которая обязана дать ноль — проверена на свежем main>
НЕ ТРОГАТЬ: <что рядом и соблазнительно, но вне карточки>

СТАРТ (первым делом, до чтения кода):
git fetch origin && git checkout -b claude/<карточка>-<2-3-слова> origin/main && npm run preflight

Перед первой правкой сверь, что ожидаемый код на месте (grep ключевых символов).
Нет его — git log origin/main -- <файл>. НЕ строй теорию, почему его нет.

ФИНИШ: npm test — сверь счёт с main (см. CLAUDE.md § Tests). Меньше = база устарела.
Затем git push -u origin HEAD. Гард дрейфа в pre-push решит, годится ли база.
```

- **ФАЙЛЫ пишутся до выдачи наряда, не после.** Гард дрейфа ловит пересечение веток по файлам, но на пуше — когда работа уже сделана. Сверить набор с открытыми PR (`gh pr list`, `git diff --name-only origin/main...<ветка>`) стоит минуту и переносит столкновение из «переделать» в «выдать другую карточку».
- **ГЕЙТ — цепочка, а не одна команда.** Правка `js/`/`css/` тянет `npm run build:sw`, иначе `test/sw-cache-name.test.js` краснеет и выглядит посторонней поломкой. Писать ровно то, что исполнитель вставит в терминал — и проверить, что оно даёт ноль на чистой базе: `prettier --check .` красен по всему репо исторически, наряд с ним учит игнорировать красный гейт.
- **Генерируемое в ФАЙЛЫ не пишут.** `sw.js` пересобирается командой, а не правится: он попадает в коммит как след правки `js/`/`css/`, но решением наряда не является. Ставить его в ФАЙЛЫ — значит объявить своим то, что одновременно принадлежит каждой соседней ветке. Конфликт по `CACHE_NAME` встаёт всегда (обе стороны машинные) и разрешается сам: драйвер `merge=ours` берёт версию базы (`.gitattributes`), после ребейза — `npm run build:sw`, дайджест считается от финального дерева. **Руками сторону не выбирать** — так уже терялся чужой `/_vercel/*` из влитого PR. Забыл пересобрать — поймает `test/sw-cache-name.test.js`.
- **Коммит по ходу:** `git add -A && git commit -m "<тип>(<область>): <что сделано>"`. Чекпоинт перед рискованным куском — тот же коммит с `checkpoint: <состояние> — до <что ломаю>`; откатываться потом дешевле.
- **База уехала — не спорить и не угадывать, спросить гард:** `node scripts/check-branch-drift.mjs`. Зелено («твои файлы в main не менялись») = отставание неважно, пушь. Блок = он перечислит файлы и коммиты, которые их переписали.
- **При блоке решает объём, а не принцип.** Конфликт мельче правки → `git rebase origin/main` и **перегнать гейт заново** (в main могли приехать новые тесты, старый зелёный не считается). Конфликт больше самой правки (кейс PP-6: 90 из 126 строк) → ветка от свежего `main` и переложить подход на актуальный файл. Идея переиспользуется, выбрасывается только приземление.
